接入文档

外部接入：让任何 OpenAI 客户端用上这些模型

本服务就是一个 OpenAI 兼容端点，外部客户端只需要改两处：base_url 指向本机 /v1，model 填清单里的 id。没有密钥、没有自定义 header、不需要装 Qoder 客户端。

1. Base URL

API key 填任意非空占位（例如 not-needed），账号池的鉴权由服务自己用设备令牌完成。

2. 模型名怎么选

GET /v1/models 返回「账号 × 模型」逐行清单，id 形如 名字-产品线@别名；把后缀抄进客户端的 model 字段就行。

Qwen3.8-Flash-qoder@a1   国际版账号 a1，走 WASM 签名加密端点
GLM-5.2-qodercn@c1       中国版账号 c1（中国版只有加密端点）
Qwen3.8-Flash-qodercn    只写产品线：在这条线的启用账号里自动选号
Qwen3.8-Flash            裸名：按账号顺序找第一个认识它、且不在排队期的
qfmodel                  Qoder 目录短名，与真实名完全等价

清单只列服务实际接受的模型。某个账号名下的模型可以在「账号和模型」页按账号取消勾选：取消后这一条从 /v1/models 消失，打到它的请求回 404；同一模型在其它账号仍开着时，裸名会自动落到那些账号。

3. curl 验一条

curl /chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"Qwen3.8-Flash-qoder@a1","stream":true,
       "messages":[{"role":"user","content":"你好"}]}'

4. Python（openai SDK）

from openai import OpenAI

client = OpenAI(base_url="/v1", api_key="not-needed")
resp = client.chat.completions.create(
    model="Qwen3.8-Flash-qoder@a1",
    messages=[{"role": "user", "content": "你好"}],
)
print(resp.choices[0].message.content)

5. Node / 浏览器 fetch

const res = await fetch("/v1/chat/completions", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    model: "Qwen3.8-Flash-qoder@a1",
    stream: true,
    messages: [{ role: "user", content: "你好" }],
  }),
});
for await (const frame of readSse(res.body)) {
  process.stdout.write(frame.choices?.[0]?.delta?.content ?? "");
}

6. 任意 OpenAI 兼容客户端

LobeChat / ChatWise / NextChat / Open WebUI / Jan / Cherry Studio 等：在「模型服务 / 自定义提供方」里新增一个 OpenAI 类型的服务，Base URL 填上面那个、API 密钥填占位串，再运行一次 GET /v1/models 同步模型清单即可。

路径别名：同一套路由也挂在 /v2 下（/v2/chat/completions 与 /v1/chat/completions 完全等价），存量配置不用改。

行为要点：stream:true 回标准 SSE，无论上游是否正常收尾都以 data: [DONE] 结束；tools / tool_calls 完整透传；上游排队与额度错误帧的 code 保真转发；403/429/排队帧会给对应账号的那个模型记 30 秒冷却，没写 @别名 的请求自动落到下一个账号。

要把这个服务部署到本机之外（局域网 / 公网），去左侧「部署文档」。

部署文档

部署与运维

从本地起服务、后台常驻、局域网共享到公网反代，一条路走到底。命令行示例默认在项目根目录执行。

1. 环境要求

Windows 或 Linux 均可，Node.js ≥ 18（pnpm run dev 的 --watch 需要 18.11+）。主接口 /v1 不依赖 qodercli，只要完成设备码登录即可；走目录模型（qfmodel 等）或中国版推理所需的 WASM 签名资产已内置在 vendor/qoder-auth-wasm.wasm。 

pnpm install
pnpm run check      # 本机体检：账号池 / 令牌 / uid / WASM 资产是否就位

2. 本地启动与登录

pnpm start          # 前台启动，默认 http://127.0.0.1:8787/
pnpm run dev        # 开发模式：8788 端口，改代码自动重启
pnpm run login      # 设备码登录（键盘菜单选产品线），可重复跑、两条产品线混着登
pnpm run login -- --product qodercn   # 跳过菜单直接登中国版
pnpm run login -- --no-browser        # 无头 / 远程机器：只打印授权链接
pnpm run clear      # 清空账号池令牌（要输 clear 确认）

登录令牌只写在 ~/.qoder-proxy/accounts.json 这一处；正在运行的服务按请求实时读池子，加账号、删账号都不用重启。服务起来后直接打开 聊天演示 或 账号和模型 就能用。

3. 后台常驻（pm2）

pm2 start pm2.config.js     # 仓库自带配置：NODE_ENV=production，超 1G 自动重启
pm2 logs qoder-proxy        # 日志在 ./logs/{out,error,combined}.log
pm2 save; pm2 startup       # 开机自启（按提示执行 startup 输出的那行命令）

4. 局域网共享

服务默认只监听 127.0.0.1。想让同一网络里其它设备用上，把 HOST 设成 0.0.0.0 重启，客户端地址里的 127.0.0.1 换成本机局域网 IP：

HOST=0.0.0.0 pnpm start                 # Linux / macOS
$env:HOST="0.0.0.0"; pnpm start          # Windows PowerShell

这一页的示例地址会跟着浏览器地址栏自动变：接入文档 里的 Base URL 始终取自你现在访问的这个 origin，不用手改。

5. 公网部署（Nginx 反向代理）

公网机器上服务仍建议只监听 127.0.0.1，由 Nginx 前置转发。仓库根目录的 vhost.conf 可直接抄进 conf.d/，关键是 proxy_read_timeout 要放宽以扛住长生成： 

server {
    listen       80;
    server_name  your-domain.com;
    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # 延长超时时间以适应 AI 生成时长
        proxy_read_timeout 60s;
        proxy_connect_timeout 60s;
    }
}

上公网前请自行加访问控制：本服务不设密钥，任何能访问到这个端口的人都能消耗你账号池的额度。至少在 Nginx 层加 Basic Auth / IP 白名单 / mTLS，或只对内网网段开放。

6. 环境变量速查

变量 默认值 说明
PORT 8787 监听端口（pnpm run dev 默认 8788）
HOST 127.0.0.1 监听地址；0.0.0.0 对局域网开放
QODER_PROXY_ACCOUNTS_FILE ~/.qoder-proxy/accounts.json 多账号凭据池（Linux/macOS 下 0600）
QODER_PRODUCT qoder 裸模型名缺省偏好的产品线
QODER_ACCESS_TOKEN 无 手工指定令牌，以只读账号 env 加入池（不可续期、不落盘）
QODER_V2_MODELS qwen-flash,qwen-plus 公开端点可用的通用模型名（仅国际版）
QODER_ENABLE_CLI 未设置 设为 1 重新开放已隐藏的 /v0 CLI 通道

7. 部署后自检

curl http://127.0.0.1:8787/health          # 期望 200：主接口与 CLI 通道状态
curl http://127.0.0.1:8787/v1/models       # 期望「账号 × 模型」清单非空
pnpm run selftest                          # 离线回归，不联网、不消耗额度
pnpm run live -- Qwen3.8-Flash-qoder@a1    # 真实登录态打上游（会消耗额度，验收时再跑）

令牌只存本机文件；容器重建 / 换机器后账号池会空，需要重新 pnpm run login，或把 ~/.qoder-proxy/accounts.json 做成持久化卷挂载进去。
